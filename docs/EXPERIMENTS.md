## 검색 (2026-10-26 계획)

정리 쪽(Q·3단계)이 바뀌면서 검색이 따라가지 못하는 빈틈을 먼저 메우고, 측정 기반 → 정책서 인덱싱 → 하이브리드 순으로 간다.
**진행 순서: S-1 → S-2 → M(멘션 교체) → 0-1 → 4-1 → 4-2 · 4-3 → 2단계(미정리 디스코드).**
미정리 디스코드 조회는 "노션에 있는 걸 제대로 찾는지"가 먼저 측정돼야 효과를 비교할 수 있어서 뒤에 둔다.
골든셋 숫자는 테스트 노션 기준이다. 팀 노션에 새로 쌓이면 기준선을 다시 잰다 (틀은 지금 만든다).

| # | 할 일 | 성공 기준 | 상태 |
|---|---|---|---|
| S-1 | 저장·갱신 후 재인덱싱 누락 막기. 승인 후 재인덱싱(`schedule_reindex`)은 이미 있지만, 건너뛰기 기준이 노션 `last_edited`(**분 단위**)라 같은 분 안의 수정·로더 로직 변경은 반영 안 됨 → **청크 내용 해시** 기준으로 | 내용이 바뀐 페이지만 다시 임베딩, 같으면 건너뜀 | ✅ 실측: 전환 후 1회 전체(99건) 재임베딩 → 재실행 99건 건너뜀 |

**3-1 결과 (2026-10-26, 테스트 노션의 별도 실험 페이지, notion-client 3.1.0 / API 2025-09-03)**
- 통합에 **댓글 읽기·삽입 권한**(Capabilities → Comment)을 켜야 한다. 꺼져 있으면 모든 댓글 호출이 `Insufficient permissions`.
- ✅ 블록 댓글: 문단·헤딩·표·**표 행** 모두 `parent={"block_id"}`로 생성되고 `comments.list(block_id)`로 다시 읽힌다. 표 행 댓글은 노션 화면에서도 해당 행에 보인다.
- ✅ 페이지 댓글, `discussion_id`로 같은 스레드에 답글, `markdown` 본문(굵게·링크).
- ✅ 멘션: 사용자(`users.list`로 ID 조회) · 페이지(근거 기록 링크용). `display_name={"type":"custom"}`로 댓글 작성자 이름 지정 가능.
- ✅ 색 블록 삽입: `blocks.children.append(..., position={"type":"after_block",...})` 또는 `after=`로 **특정 블록 바로 뒤**에 넣을 수 있다 (콜아웃 `yellow_background` 등).
- ⚠️ 표 행의 자식으로 블록 append → API는 성공하지만 노션 화면에 안 보인다. 쓰지 않는다.
- ⚠️ 표 셀 글자 색 변경은 되지만 원문 블록 수정이라 원칙상 쓰지 않는다.
**3-2~3-4 구현 메모 (2026-10-26)**
- 로더: 블록 트리를 통째로 가져와(`fetch_tree`) 순수 함수(`parse_tree`)로 파싱. 페이지 수정 시각이 같으면 `data/spec/` 캐시 사용.
  화면 목록 표·"항목|내용" 표는 화면 정보로, ID 없는 표(공통 규칙)는 ID 없는 항목으로. 복사로 생긴 중복 행은 접히는 제목 안쪽을 대표로 남기고, 내용이 다르면 "충돌" 경고.
  제목 색·버전 표시는 규칙이 없어 메타데이터로만 둔다.
- 매칭: 정책서별 LLM 1회. 판정 skip / same / modify / new / unknown, 목록에 없는 ID는 한 단계 보수적으로 내린다(modify→new→unknown). same은 ID가 틀려도 그대로 둔다(쓸 게 없는 판정).
  - skip(정책서 대상 아님): 디자인 리소스(아이콘·색)·피그마 시안 오류 수정·컴포넌트 구현 방식. 사용자 피드백으로 추가.
  - "애매하면 보수적으로 new" 규칙이 오히려 제안을 **더 만들었다** (이미 다른 항목에 있는 내용을 위치가 애매하다고 new로). → "애매하면 제안을 덜 만드는 쪽(same·skip), 결정에 없는 세부를 추측하지 않는다"로 변경.
  - 매칭만 다시 돌려 보기: `python -m scripts.spec_match_preview --approved-by <승인자>` (노션 쓰기 없음). 정답 라벨 `data/spec/labels.json`이 있으면 정확도 출력.
  - skip은 **결정의 종류**로만 판단한다. "이 정책서에 화면이 없음"을 skip으로 답해 문구 변경 결정이 버려졌다 → 프롬프트에 "그건 unknown"을 명시. 혼자 매칭할 때와 여러 건을 같이 매칭할 때 판정이 달랐다(같이 넣으면 unknown, 혼자면 skip).
- **미분류 제안 페이지** (`NOTION_SPEC_INBOX_PAGE`, `scripts/setup_spec_inbox.py`): 맞는 정책서가 없는 제안을 체크박스로 모은다. PM이 반영할 곳을 정하고 체크해서 닫는다.
  - 가는 경우: 기능영역에 정책서가 없음(매칭 LLM 호출 없이 바로), 기본 정책서(`*`)로 넘어갔는데 위치를 못 찾음.
  - 영역의 정책서 안에서 위치만 못 찾은 unknown은 그 정책서의 페이지 댓글로 둔다.
  - 이유: 기본 정책서에 페이지 댓글로 달면 북마크 명세서에 프로필 제안이 붙는 식으로 엉뚱한 문서가 지저분해지고, 디스코드에만 보고하면 잊힌다.
  - 저장된 기록 다시 반영: `python -m scripts.reflect_saved --record <기록ID>` (같은 기록은 행 댓글·미분류 페이지에 중복으로 넣지 않음).
- 반영 대상: `SPEC_REFLECT_STATUSES`(기본 최종결정). 정책서는 `NOTION_SPEC_PAGES`의 영역별 페이지, 없으면 `*` 기본 정책서 — 영역 분류(지도·탐색)와 정책서 구분(북마크 명세서의 탐험 화면)이 어긋나는 경우가 실제로 있었다.
- 실측 (스레드 3개 → 결정 11건, 최종결정 9건): 행 댓글 3 · 새 항목 콜아웃 2 · 페이지 댓글 2 · 이미 반영됨 2. 잘못된 반영 1건(same을 new로 내리던 정규화 버그 → 수정).
  지켜볼 점: 디자인시스템 구현 결정·다른 기능 결정이 기본 정책서의 페이지 댓글로 들어간다. 노이즈가 많으면 `*`를 빼거나 unknown은 댓글 대신 디스코드에만 보고.
- 정책서 구조 메모: 정책 ID가 제목이 아니라 **표 행의 첫 칸**에 있다 (화면 ID = 접히는 제목, 기능 ID = 표 행). 3-2 로더는 표 행 단위로 파싱하고, 같은 내용이 페이지에 중복된 경우·ID 칸이 빈 행(윗행 이어받기)을 처리해야 한다.
